Alright, now that we have a Kubernetes cluster running ([previous post](http://127.0.0.1:4000/tech/2024/02/01/kubernetes.html)), we have to install some applications 🚀!

I decided to first go with Jellyfin, an open source Media System. It is a good first project since it requires the configuration of a simple deployment, a load balancer, and a persistent volume.

The main configuration is pasted at the end of the article, and some details on some of the sections are described below.

## Volumes

The main deployment contains a few section (see full code at end), the following defined the *Volumes* where media files are stored. For my setup, which consists of three VMs, I mounted the folder containing my media (on the host machine) to all the VMs (named `nas`). All the paths shown in `volumePaths` are subdirectories of the shared folder.

```yaml
volumeMounts:
  - mountPath: "/Movies"
    readOnly: false
    name: nas
    subPath: Movies
  - mountPath: "/Shows"
    readOnly: false
    name: nas
    subPath: Shows
  - mountPath: "/config"
    readOnly: false
    name: nas
    subPath: config
  - mountPath: "/cache"
    readOnly: false
    name: nas
    subPath: cache
volumes:
  - name: nas
    persistentVolumeClaim:
      claimName: pvc-jellyfin-nas
```

### Notes
- to mount a folder in a Linux VM, we must install the `vmware-tools` package (`pacman -S open-vm-tools`), setup a systemd service, and add an entry to fstab (more details in [VMware/Install Arch Linux as a guest](https://wiki.archlinux.org/title/VMware/Install_Arch_Linux_as_a_guest#Open-VM-Tools))
- the volume can be a folder, a separate disk, or be full NAS server
- the `name` associates a mountPath with its respective `volume`

## Kubernetes Persistent Volume and Claim
To make the node drive available to the cluster pods, we need to create a Persistent Volume (PV) and a persistent Volume Claim (PVC), again, the name (`nas`) has to match. The volume is mounted on the node at `/mnt/nas/jellyfin`.

Those two resources are pretty simple and self explanatory:
```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pv-jellyfin-nas
  labels:
    type: local
spec:
  storageClassName: manual
  capacity:
    storage: 10Gi
  accessModes:
    - ReadWriteMany
  hostPath:
    path: "/mnt/nas/jellyfin"
```
and the claim:
```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: pvc-jellyfin-nas
  namespace: jellyfin
spec:
  storageClassName: manual
  accessModes:
    - ReadWriteMany
  resources:
    requests:
      storage: 10Gi
```
the option `ReadWriteMany` means that the volume can be mounted as read-write by many nodes. The size of the request has to match the volume capacity so they can be assigned!

## Retain Configuration

For the Jellyfin server to retain its configuration when the pod restarts---or the cluster is shutdown---we must create and assigned a `/config` folder (shown above). Otherwise, the folder will be created on the pod, and the settings will be lost when the pod is shutdown. Similarly, the `cache/` folder where metadata can be saved.

## LoadBalancer

By default, the server will only be accessible through a `ClusterIP`, which is only accessible from within the Kubernetes cluster. Kubernetes offer two other types of service:
- `NodePort`: allows for remote access to the cluster node where the application is running
- `LoadBalancer`: allows for remote access to the main node and redirect the traffic internally to the correct `NodePort`.

We could use a `NodePort` and making sure our server is always running on the same node to have a static IP, but in general this option is only used for testing. For those reasons, I decided to go with a `LoadBalancer`.

```yaml
apiVersion: v1
kind: Service
metadata:
  labels:
    app: jellyfin
  name: jellyfin
  namespace: jellyfin
spec:
  ports:
  - name: web-tcp
    port: 8096
    protocol: TCP
    targetPort: 8096
    nodePort: 30000
  - name: web-udp
    port: 8096
    protocol: UDP
    targetPort: 8096
    nodePort: 30001
  selector:
    app: jellyfin
  type: LoadBalancer
    protocol: UDP
    targetPort: 8096
    nodePort: 30001
  selector:
    app: jellyfin
```

# Applying to the cluster and accessing the server

I saved the main deployment file to `deployment.yaml`, the `pv.yaml`, and `pvc.yaml` in a common `jellyfin/` directory. The configuration can be applied to the Kubernetes cluster using `kubectl apply -f jellyfin/`. Once the pod is running, the server should be accessible at the port specify in the `LoadBalancer` configuration.

First we can see that the main server is running:
```zsh
> kubectl get pods -n jellyfin
NAME                        READY   STATUS    RESTARTS      AGE
jellyfin-669cbb7dff-mgjwm   1/1     Running   5 (25m ago)   21d
```
and that the `LoadBalancer` is redirecting the traffic:
```zsh
> kubectl get svc -n jellyfin
NAME       TYPE           CLUSTER-IP     EXTERNAL-IP   PORT(S)                         AGE
jellyfin   LoadBalancer   10.96.72.180   <pending>     8096:30000/TCP,8096:30001/UDP   22d
```
as noted above, the TCP port is used for the web interface, and the UDP for the data transfer.

To connect to our interface, we navigate to `KUBERNETES_CLUSTER_IP:30000`. On the first login, after completing the guided configuration, you should have access to your media server. Once it is configured, it can also be accessible on the TV using the same URL. More details on the TV app if you have a Samsung TV in the next section.

Note: The naming schemes and directories organization have to follow a predefined pattern to be automatically recognized by Jellyfin. See more details on the documentation ([Movies](https://jellyfin.org/docs/general/server/media/movies) and [Shows](https://jellyfin.org/docs/general/server/media/shows)).

# Bonus

If like myself you have a Samsung TV, there is a last step. Since the Jellyfin app is not available in the TV's store, we must manually installed the [application](https://github.com/jellyfin/jellyfin-tizen).

First, the TV has to be put in Developer's mode, this is done by:
1. Open the Smart Hub.
2. In the "Apps" panel, enter "12345".
3. Switch Developer mode to "On".
4. Enter the IP of the computer that you will used to connect to the TV.

Then, we can push the Jellyfin app to the TV. Tim Georift built a Docker image (GitHub [Georift/install-jellyfin-tizen](https://github.com/Georift/install-jellyfin-tizen)) to install the latest app (GitHub [jellyfin/jellyfin-tizen](https://github.com/jellyfin/jellyfin-tizen)) to a TV.

You can install the app with a single command:
```zsh
> docker run --rm georift/install-jellyfin-tizen <samsung tv ip>
```

## Complete configuration

```yaml
---
apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
    app: jellyfin
    app.kubernetes.io/instance: jellyfin
    app.kubernetes.io/name: jellyfin
  name: jellyfin
  namespace: jellyfin
spec:
  replicas: 1
  selector:
    matchLabels:
      app: jellyfin
  template:
    metadata:
      labels:
        app: jellyfin
        app.kubernetes.io/name: jellyfin
    spec:
      containers:
      - image: jellyfin/jellyfin
        imagePullPolicy: Always
        name: jellyfin
        ports:
        - containerPort: 8096
          name: web
          protocol: TCP
        env:
        - name: TZ
          value: "America/New York"
        volumeMounts:
        - mountPath: "/Movies"
          readOnly: false
          name: nas
          subPath: Movies
        - mountPath: "/Shows"
          readOnly: false
          name: nas
          subPath: Shows
        - mountPath: "/config"
          readOnly: false
          name: nas
          subPath: config
        - mountPath: "/cache"
          readOnly: false
          name: nas
          subPath: cache
      volumes:
        - name: nas
          persistentVolumeClaim:
            claimName: pvc-jellyfin-nas
```
