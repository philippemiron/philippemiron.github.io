## Paths and volumes

The main deployment contains a few section, the following defined the *Volumes* where media files are stored. For my setup, which consists of three VMs, I mounted the folder containing my media (on the host machine) to all the VMs (named `nas`). 

The section of the deployment controlling the following is shown below. All the paths shown in `volumePaths` are subdirectories of the shared folder. Note that this volume could as well be located on a separate disk, or be full NAS server.

```
volumeMounts:
  - mountPath: "/Movies"
    readOnly: false
    name: nas
    subPath: Movies
  - mountPath: "/Shows"
    readOnly: false
    name: nas
    subPath: Shows
  - mountPath: "/config"
    readOnly: false
    name: nas
    subPath: config
  - mountPath: "/cache"
    readOnly: false
    name: nas
    subPath: cache
volumes:
  - name: nas
    persistentVolumeClaim:
      claimName: pvc-jellyfin-nas
```

To make this work, we need to create a Persistent Volume (PV) and a persistent Volume Claim (PVC), note that the name (`nas`) matches the PV names. Those two resources are pretty simple:

```
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pv-jellyfin-nas
  labels:
    type: local
spec:
  storageClassName: manual
  capacity:
    storage: 10Gi
  accessModes:
    - ReadWriteMany
  hostPath:
    path: "/mnt/nas/jellyfin"
```
and the claim:
```
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: pvc-jellyfin-nas
  namespace: jellyfin
spec:
  storageClassName: manual
  accessModes:
    - ReadWriteMany
  resources:
    requests:
      storage: 10Gi
```

## Retain Configuration

For the Jellyfin server to retain it's configuration when the pod restarts, or the cluster is shutdown), we must create a `/config` folder (shown above) on a shared drive, accessible by the server. If not specifically defined in the configuration, the folder will be created on the pod, and the settings will be lost when the pod is shutdown.

## LoadBalancer

Finally, by default, the server will only be accessible through a `ClusterIP`. The make it accessible to our network (and outside of the cluster!), we must change the service type to a `LoadBalancer`. See the complete configuration below. 

## Complete configuration

```
---
apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
    app: jellyfin
    app.kubernetes.io/instance: jellyfin
    app.kubernetes.io/name: jellyfin
  name: jellyfin
  namespace: jellyfin
spec:
  replicas: 1
  selector:
    matchLabels:
      app: jellyfin
  template:
    metadata:
      labels:
        app: jellyfin
        app.kubernetes.io/name: jellyfin
    spec:
      containers:
      - image: jellyfin/jellyfin
        imagePullPolicy: Always
        name: jellyfin
        ports:
        - containerPort: 8096
          name: web
          protocol: TCP
        env:
        - name: TZ
          value: "America/New York"
        volumeMounts:
        - mountPath: "/Movies"
          readOnly: false
          name: nas
          subPath: Movies
        - mountPath: "/Shows"
          readOnly: false
          name: nas
          subPath: Shows
        - mountPath: "/config"
          readOnly: false
          name: nas
          subPath: config
        - mountPath: "/cache"
          readOnly: false
          name: nas
          subPath: cache
      volumes:
        - name: nas
          persistentVolumeClaim:
            claimName: pvc-jellyfin-nas
---
apiVersion: v1
kind: Service
metadata:
  labels:
    app: jellyfin
  name: jellyfin
  namespace: jellyfin
spec:
  ports:
  - name: web-tcp
    port: 8096
    protocol: TCP
    targetPort: 8096
    nodePort: 30000
  - name: web-udp
    port: 8096
    protocol: UDP
    targetPort: 8096
    nodePort: 30001
  selector:
    app: jellyfin
  type: LoadBalancer
    protocol: UDP
    targetPort: 8096
    nodePort: 30001
  selector:
    app: jellyfin
```

# Applying to the cluster and accessing the server

I saved the main deployment file to `deployment.yaml`, the `pv.yaml`, and `pvc.yaml` in a common `jellyfin/` directory. The configuration can be applied to the Kubernetes cluster using `kubectl apply -f jellyfin/`. Once the pod is running, the server should be accessible at the port specify in the `LoadBalancer` configuration.

# Bonus

If like myself, you have a Samsung TV, there is an ultimate step since the Jellyfin app is not available in the TV's store. First, the TV has to be put in Developer's mode, this is done by:
1. Open the Smart Hub.
2. In the "Apps" panel, enter "12345".
3. Switch Developer mode to "On".
4. Enter the IP of the computer that you will used to connect to the TV.

Then, we can push the Jellyfin app to the TV. Tim Georift built a Docker image to install the latest app to a TV [repo](https://github.com/Georift/install-jellyfin-tizen).

```
> docker run --rm georift/install-jellyfin-tizen <samsung tv ip>
```
